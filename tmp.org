
● Two answers here, and the second one matters more.

  1. Your cache already has JUnit — nothing to transfer

  Both versions are fully cached and offline-resolvable (jar + pom + descriptor.bin), including JUnit 4's required transitive dep:

  ┌────────────────────────────────┬───────────────────────────┐
  │            Artifact            │          Cached?          │
  ├────────────────────────────────┼───────────────────────────┤
  │ junit:junit:4.12               │ ✅ jar + pom + descriptor │
  ├────────────────────────────────┼───────────────────────────┤
  │ junit:junit:4.13.2             │ ✅ jar + pom + descriptor │
  ├────────────────────────────────┼───────────────────────────┤
  │ org.hamcrest:hamcrest-core:1.3 │ ✅ (pulled in by junit 4) │
  └────────────────────────────────┴───────────────────────────┘

  So the other assistant's worry ("run once without --offline to populate the cache") doesn't apply — 4.13.2 will resolve offline. That said, I'd use testImplementation(libs.junit) (=
   4.12, the catalog pin already used by test/, cuis-test/, subapp-example/) rather than hardcoding junit:junit:4.13.2. Both work offline; the catalog form is consistent with the rest
   of the project.

  2. The dependency won't actually fix your error

  Look at which task failed: :cuis-server:compileJava — that's the main compile, not compileTestJava. The base cuis-server/build.gradle.kts does this:

  sourceSets {
      main { java { setSrcDirs(listOf("src")) } }   // main root = "src"
  }

  Your test lives at src/test/java/.../CuisServerIntegrationTest.java — which is underneath src, so it gets swept into the main source set and compiled by compileJava, where JUnit is
  (correctly) absent. A testImplementation dependency only adds JUnit to the test classpath, so the main compile will keep failing on org.junit no matter which JUnit version you add.

  The real fix is to keep test sources out of main:

  dependencies {
      // ...existing...
      testImplementation(libs.junit)
  }

  sourceSets {
      main {
          java {
              setSrcDirs(listOf("src"))
              exclude("test/**")          // don't compile src/test as main
          }
      }
      test {
          java {
              setSrcDirs(listOf("src/test/java"))
          }
      }
  }

  After that, ./gradlew --offline :cuis-server:test should compile and run against the already-cached JUnit 4.12 + hamcrest — no online build, no cache transfer needed.
